# PanDao — продакшен: сборка, SEO-пререндер и деплой на Beget

Этот лендинг сейчас работает как **UI-кит**: JSX компилируется прямо в браузере
через `@babel/standalone`. Для боевого сайта так оставлять нельзя — медленно и
поисковики видят пустую страницу. Ниже — что сделать, чтобы превратить его в быстрый
статический сайт + простую PHP-админку на shared-хостинге Beget.

## 2. Главное: собрать через Vite (убрать Babel из браузера)

Babel в рантайме — самый большой тормоз. Собираем локально на компьютере (не на
Beget — там нет Node), а на хостинг заливаем готовую статику.

### Шаги (на вашем компьютере, нужен Node 18+)

```bash
# 1. создать проект
npm create vite@latest pandao -- --template react
cd pandao
npm install

# 2. перенести файлы из ui_kits/website/:
#    - все *.jsx  → src/  (Hero.jsx, Header.jsx, и т.д.)
#    - kit.css, effects.js → src/
#    - assets/ (webp, png) → public/assets/
#    - legal/, robots.txt, sitemap.xml, favicon.svg → public/
```

### Что поправить при переносе JSX

Сейчас компоненты «общаются» через `window` (`Object.assign(window, {...})`) — так надо
для браузерного Babel. В Vite замените на нормальные импорты:

```js
// было (в конце файла): Object.assign(window, { Hero });
// стало:
export default function Hero() { ... }      // в Hero.jsx
// и в main.jsx:
import Hero from './Hero.jsx';
import './kit.css';
```

`main.jsx`:
```jsx
import React from 'react';
import { createRoot } from 'react-dom/client';
import Header from './Header.jsx';
import Hero from './Hero.jsx';
// ...остальные секции
import './kit.css';

function App() { return (<div className="pd-site">{/* секции */}</div>); }
createRoot(document.getElementById('root')).render(<App />);
```

В `index.html` (корень проекта Vite) оставьте только `<head>` (мета/SEO целиком
скопируйте из текущего файла), `<div id="root">`, `<noscript>` и
`<script type="module" src="/src/main.jsx">`. **Уберите** все теги `unpkg.com`
(react/babel/lucide) — Vite соберёт это сам. Lucide ставится как пакет: `npm i lucide-react`.

```bash
# 3. собрать
npm run build      # появится папка dist/ — это и есть боевой сайт
```

## 3. SEO-пререндер (чтобы поисковик видел текст)

После сборки контент всё ещё рендерится на клиенте. Для лендинга проще всего
**пререндер в статический HTML**:

```bash
npm i -D vite-plugin-prerender-spa   # или vite-prerender-plugin
```
…либо самый простой путь без плагинов — **`react-snap`**:
```bash
npm i -D react-snap
# в package.json:  "scripts": { "postbuild": "react-snap" }
npm run build
```
`react-snap` прогонит сайт в headless-браузере и положит в `dist/index.html` уже
готовую разметку с текстом. Поисковики и превью в мессенджерах увидят контент сразу.

> Альтернатива по-серьёзному: перевести на **Next.js** (SSG/`output: export`) — даст
> чистый статический экспорт с SEO «из коробки». Но это больше переделок.

## 4. Деплой на Beget (shared)

1. В панели Beget откройте файловый менеджер или подключитесь по **FTP/SFTP**.
2. Содержимое папки **`dist/`** залейте в корень сайта — обычно
   `~/<домен>/public_html/`.
3. Проверьте, что `index.html`, `assets/`, `legal/`, `robots.txt`, `sitemap.xml`,
   `favicon.svg` лежат в корне.
4. Beget по умолчанию отдаёт `index.html` — сайт заработает сразу.

### `.htaccess` (Apache на Beget) — кэш и сжатие

Положите в корень файл `.htaccess`:
```apache
# Gzip
<IfModule mod_deflate.c>
  AddOutputFilterByType DEFLATE text/html text/css application/javascript application/json image/svg+xml
</IfModule>
# Кэш статики
<IfModule mod_expires.c>
  ExpiresActive On
  ExpiresByType image/webp "access plus 1 year"
  ExpiresByType text/css "access plus 1 month"
  ExpiresByType application/javascript "access plus 1 month"
  ExpiresByType image/svg+xml "access plus 1 year"
</IfModule>
# SPA-фолбэк (если используете клиентский роутинг)
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteBase /
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule . /index.html [L]
</IfModule>
```

## 5. PHP-админка + приём заявок (для вашей панели)

Форма на сайте сейчас «фейковая» (UI-кит). Чтобы заявки приходили, добавьте простой
PHP-обработчик. Пример `api/lead.php` (Beget поддерживает PHP на shared):

```php
<?php
header('Content-Type: application/json; charset=utf-8');
$name  = trim($_POST['name']  ?? '');
$phone = trim($_POST['phone'] ?? '');
if ($name === '' || $phone === '') {
  http_response_code(422);
  echo json_encode(['ok' => false, 'error' => 'Заполните имя и телефон']); exit;
}
// 1) письмо на почту
$to = 'info@ваш-домен.ru';
$msg = "Имя: $name\nТелефон: $phone\nДата: " . date('Y-m-d H:i');
@mail($to, 'Новая заявка с сайта PanDao', $msg, "From: site@ваш-домен.ru");
// 2) сохранить в файл/БД для админки
file_put_contents(__DIR__.'/leads.csv',
  date('c').";".str_replace(';',',',$name).";".str_replace(';',',',$phone)."\n",
  FILE_APPEND | LOCK_EX);
echo json_encode(['ok' => true]);
```

В `ContactModal.jsx` замените эмуляцию отправки на реальный `fetch`:
```js
await fetch('/api/lead.php', {
  method: 'POST',
  headers: { 'Content-Type': 'application/x-www-form-urlencoded' },
  body: new URLSearchParams({ name, phone })
});
```

Для **простой админки** (просмотр заявок) на shared-хостинге достаточно одной
PHP-страницы с паролем (`password_verify`) и чтением `leads.csv` или таблицы MySQL
(Beget даёт MySQL в панели). Для управления контентом без пересборки можно вынести
тексты/телефоны в `data.json` и читать его на фронте — тогда правки в админке не
требуют повторной сборки Vite.

# 7. Ревью сайта — две роли

Прошёлся по лендингу дважды: сначала как **маркетолог**, потом как **дизайнер**.
Каждое ревью — отдельно. Пункты со звёздочкой (★) я уже не могу сделать в рамках
UI-кита — это задачи для боевой версии (нужен бэкенд, реальные данные, аналитика).

## 7.1 Ревью маркетолога

**Что работает хорошо**
- Чёткое УТП в первом экране: «откуда → куда» + конкретные города. Сразу понятно, кому
  и что мы везём.
- Сильный приём доверия в «Фактах»: публикуем даже потери и то, что возместили ущерб.
  Это редкость в нише и реально продаёт.
- Прямая трансляция со склада — мощный сигнал прозрачности, выделяет среди карго.
- Мессенджеры (WhatsApp/Telegram) на видном месте — это родной канал аудитории карго.

**Что я бы усилил (по приоритету)**
1. **Калькулятор стоимости.** Аудитория хочет цифру сразу. Сейчас всё ведёт в форму.
   Даже грубый расчёт «город + вес + тип → вилка цены/срока» резко поднимет конверсию. ★
2. **Отзывы и кейсы.** 1200+ клиентов заявлено, но ни одного живого голоса. Нужны
   2–3 отзыва (имя, ниша, цитата) или мини-кейс «везли X → срок → результат». ★
3. **Оффер/триггер действия.** Нет причины оставить заявку «прямо сейчас». Добавить
   мягкий оффер: «Рассчитаем за 15 минут», «Бесплатная проверка поставщика к первой
   отправке» — снимает прокрастинацию.
4. **Гарантии рядом с CTA.** Бейджи «договор · страховка · возмещение ущерба» возле
   кнопки расчёта закрывают страх «кинут».
5. **Конкретика в цифрах срока.** «18–30 дней» есть только в FAQ. Вынести средний срок
   на видное место — это вопрос №1 у клиента.
6. **Призыв в конце контактов.** Блок контактов хорош, но финальный экран мог бы
   повторять главный оффер + дедлайн ответа.
7. **Аналитика и пиксели.** Подключить Яндекс.Метрику (вебвизор + цели на заявку и
   клики по мессенджерам) и при рекламе — пиксели. Без этого не измерить конверсию. ★
8. **Квиз-лид-магнит.** Для холодного трафика хорошо заходит мини-квиз («что везёте?»)
   с расчётом в конце — собирает контакты лучше «голой» формы. ★

**Текст**
- Заголовки и карточки переписаны под «человеческий» тон — это плюс. Дальше держать
  один голос: «вы/ваш», коротко, без канцелярита.
- Добавить микрокопию под кнопкой формы: «Перезвоним за 15 минут, без спама».

## 7.2 Ревью дизайнера

**Что работает хорошо**
- Сильная и цельная система: один акцент (тёмно-алый), чёткая типографика Onest,
  единые радиусы/тени, ритм светлых и тёмных секций.
- Узнаваемый мотив (карта, координаты, крестики-маркеры, пунктирные маршруты) проходит
  через весь сайт — это фирменный стиль, а не набор блоков.
- Контраст секций (светлый/серый) разведён, переходы читаются.
- Микроанимации (count-up, параллакс, hover-иконки, прелоадер, скролл-маршрут) дают
  «живость» без перегруза. Процесс на складе теперь читается за счёт значков.

**Что я бы доработал (по приоритету)**
1. **Единая сетка иконок.** Сейчас в услугах — эмодзи, в остальных блоках — линейные
   иконки Lucide. Это стилевой разнобой. Рекомендую везде один набор (Lucide) ИЛИ
   везде эмодзи. Мой выбор — Lucide во всех блоках для премиальности; эмодзи оставить
   максимум как акцент. (Сделал по вашему запросу эмодзи в услугах — но как дизайнер
   флагаю несогласованность.)
2. **Реальные фото склада/порта.** Плашки процесса и hero — заглушки/кропы. Настоящие
   HD-фото поднимут доверие сильнее любой графики. ★ (нужны исходники от вас)
3. **Консистентность скруглений.** Кое-где радиусы 14/16/18/20/22/26 — стоит свести к
   3 значениям (например 14 / 18 / 26) для строгости.
4. **Состояния форм.** Проверить фокус/ошибки/успех в модалке заявки на всех экранах —
   важно для ощущения качества.
5. **Доступность (a11y).** Проверить контраст серого текста на сером фоне (WCAG AA),
   видимый `:focus` на кнопках/ссылках, `aria-label` у иконочных кнопок (частично есть).
6. **Тёмная панель статистики под видео.** Стало компактнее (иконка+число в строку).
   Можно ещё выровнять базовые линии чисел между ячейками для аккуратности.
7. **Пустые состояния параллакса на слабых устройствах.** Уже учтён
   `prefers-reduced-motion` — хорошо; проверить плавность на бюджетных Android.
8. **Favicon.** Сейчас простой SVG-плейсхолдер («P»). Заменить на нормальный знак
   из логотипа. ★

**Вывод обеих ролей:** фундамент сильный и продающий. Следующий шаг номер один —
**калькулятор + отзывы** (маркетинг) и **реальные фото + единые иконки** (дизайн).
```
